### 部署后端 500 排查（"服务器内部错误，请检查后端数据库连接配置。"）
- **根因**：部署到 Vercel 的后端没有配置生产数据库。`backend/app/core/config.py` 的默认 `APP_DATABASE_URL` 是 `postgresql+asyncpg://...@localhost:5432/time_budget_tracker`，Vercel 上根本没有这个 PostgreSQL。`APP_*` 环境变量在 Vercel Project 未设置 → 所有数据库请求 500。
- **代码修复**：`backend/app/main.py` `/health` 原本直接执行 DB 查询无 try/except，DB 不通时返回 500（更糟糕：连探针都炸了）。改为 try/except + HTTPException(503) + 返回 `{"detail":{"status":"error","database":"error","detail":"<异常摘要>"}}`，方便日志快速分辨"进程活着但 DB 不通"。
- 测试：pytest 79 全过；docs/deployment.md 同步说明新行为。
- **真正的部署修复**（需要用户操作，见部署文档 §二.2-3）：
  1. Supabase 项目准备好（Session pooler），URL 中 密码 URL 编码。
  2. 在 Supabase 上跑 migrations（`alembic upgrade head`，Vercel 不会自动跑迁移）。
  3. Vercel Project → Settings → Environment Variables（Production）：
     - 前端构建：`VITE_API_BASE_URL=/api/v1`、`VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY`
     - 后端运行：`APP_ENVIRONMENT=production`、`APP_SECRET_KEY`（≥32）、`APP_DATABASE_URL`、`APP_DATABASE_ROLE=dayflow_app`、`APP_AUTH_PROVIDER=supabase`、`APP_SUPABASE_URL`、`APP_SUPABASE_PUBLISHABLE_KEY`、`APP_CORS_ORIGINS=["https://dayflow.com.cn","https://www.dayflow.com.cn"]`
  4. Redeploy。
