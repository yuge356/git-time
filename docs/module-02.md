# 模块 2：层级任务与时间预算

## 本模块范围

- 创建课程、章节、小节、练习和项目实践等层级任务
- 修改任务标题、上级任务、预计学习时间和状态
- 软删除任务及其全部子任务
- `TODO`、`IN_PROGRESS`、`PAUSED`、`BLOCKED`、`DONE` 状态流转
- 80%、100%、150% 时间预算阈值计算
- 层级规则：项目 → 模块 → 任务，任务下还允许再添加一层子任务（子任务不能再继续添加下级）；含子任务的任务作为容器管理，不能直接计时或加入每日计划
- 任务树所有权隔离和 PostgreSQL RLS
- 数据库级同所有者父子约束和防循环触发器
- 任务树与大纲列表两种项目视图，切换选择保存在浏览器本地
- 项目页的成功、失败、校验和本地缓存提醒统一显示中文；任务写入 IndexedDB 前转换为可序列化的普通对象，避免响应式对象触发 `DataCloneError`
- 项目、模块和任务统一使用模态弹窗创建或编辑
- 新建可执行任务时计划用时必须大于 0；小时和分钟同时为 0 时不会保存，弹窗显示红色中文提醒
- 修改可执行任务的计划用时后，同步更新今天及未来日期中引用该任务的每日计划条目；历史日期保持原始快照
- 新建或修改任务后，**已安排在今天**的叶子任务会自动导入每日计划，无需手动添加：截止日期为今天、重复规则匹配今天，或今天落在“安排开始～安排结束”计划窗口内三者任一命中即可；服务端补齐与前端本地补齐使用同一条规则，含子任务的容器任务和已完成任务不会被导入
- 项目中不再提供“每日提醒”与“默认提醒”开关：安排好的任务直接出现在今日任务里，不再依赖单独的提醒设置；保存任务时会清空历史遗留的提醒时间
- 可执行任务的编辑弹窗把全部日期收进一个“安排时间”分区，按三种方式分列并各自说明：①连续做几天（安排开始→安排结束，与今日页甘特图的拖拽排期是同一份计划窗口）、②按规律重复（重复规则 + 重复结束日期，选“不重复”时结束日期自动隐藏）、③只在截止当天（截止日期）。项目与模块没有排期概念，截止日期仍留在优先级旁边
- 项目模板：内置“学习课程 / 项目推进 / 考试备考 / 读书计划 / 习惯养成”预设，可在“模板库”中新建、编辑或删除自己的模板；编辑内置预设会保存为用户自己的副本并在选择器中取代该预设。新建项目时可直接选择模板，创建后按模板大纲逐级生成模块与任务
- 节点折叠、拖拽调整层级、缩放、进度/优先级/截止日期展示；任务树模式下每个项目拥有独立画布，节点保持固定大小，画布在面板内滚动、不撑破页面框架；调整窗口大小时画布内容不缩放，被遮住的部分通过画布滚动查看，也可用工具栏手动缩放
- 独立任务依赖边、带箭头虚线展示及循环依赖校验

任务 API 保留了 `actual_seconds`、`budget_usage_ratio` 和 `budget_level` 字段。

今日页**正在计时**时，任务树会把这段尚未落库的时长实时计入对应任务，并沿父链汇总到模块与项目：
项目页的进度条、已用/剩余时间与今日页的计时器同步跳动。计时暂停或结束时，前端把本次新增的实际
时长（含沿父链的汇总）写入本地任务缓存，因此数值不会回退；权威汇总仍以服务器按 Session 聚合的
结果为准，下次后台刷新自动校正。合并服务器数据时，本地已应用的累计时长只会上调不会回退（会话快照
仍在后台重放，服务器聚合可能短暂滞后）。

项目与模块（子项目）都可在“更多操作”菜单中**标记完成**（或恢复）：完成的项目从项目页列表隐藏
（面板提供“显示已完成项目”开关可查看与恢复），完成的模块显示完成徽标；两者之前的计时数据完整
保留，历史记录（时间统计、计划进度表）中仍可查询。服务端允许容器节点仅变更自身 `status`
（DONE / 恢复），任务与其它容器字段的生命周期仍由子任务推导，不可直接设置。
模块 3 已接入 Session 聚合，以上字段现在返回真实学习时长和预算状态。

新增 `tasks` 表主要字段：

- `id`
- `owner_id`
- `parent_id`
- `title`
- `node_type`
- `priority`
- `due_date`
- `planned_start_date` / `planned_end_date`（迁移 0016；仅 `TASK` 使用，今日页甘特图计划窗口，
  可在甘特图上拖拽调整，项目 / 模块节点恒为空且接口拒绝设置）
- `status`
- `estimated_seconds`
- `sort_order`
- `completed_at`
- `deleted_at`
- `created_at`
- `updated_at`

项目模板保存在独立的 `project_templates` 表中：模板结构是 JSON 蓝图而不是任务行，因此模板不会
出现在项目页、时间统计或每日计划里，直到用户把它应用到一个新项目。表启用与任务表相同的
owner-only RLS。

任务依赖保存在独立的 `task_dependencies` 表中，不嵌入任务树布局。这样任务数据可以被任务树、
大纲列表、后续看板、日历和甘特图共同复用。服务端拒绝自身依赖、跨用户依赖和循环依赖。

## 项目页面交互

- 右上角“任务树 / 大纲列表”切换控制同一份任务数据的呈现方式。
- 项目列表的历史计时由数据库按任务聚合后返回，不再把全部历史计时明细加载到应用内存；正在计时的增量仍实时计入父级汇总。
- 项目色彩识别系统：每个项目根据唯一 ID 确定性映射专属主题色，在大纲列表和任务树模式中保持永久一致；下属模块与任务继承该项目主题色，用于左侧竖线、树状连接线和拖拽高亮。全部色板取自品牌紫色（#7c5cfc）同一色系的 8 档深浅变化（紫罗兰、葡萄紫、靛蓝、紫红、薰衣草紫、深梅紫、长春花紫、兰花紫），今日页甘特图等页面复用同一映射，保证同一项目跨页面颜色一致。
- 任务树整体采用 Apple Liquid Glass 风格，结合 2.5D 扁平化设计，从左向右展示父子关系；每个项目一块独立画布（带项目名、主题色圆点与完成进度）；**画布高度按任务树自身在默认尺寸下的高度渲染**，任务少的项目不再留下大片空白，任务多的项目直接展开（超过 2400px 才在画布内滚动，也可用标题旁的折叠按钮收起）；节点默认 100% 固定大小渲染，调整窗口大小时内容大小不变、仅被画布裁剪，需要时可手动缩放。
- 任务树模式下每个项目标题右侧提供折叠/展开按钮（箭头指示状态），可按需收起或展开该项目下方的任务树画布；再次展开时画布布局自动重新测量。
- 节点之间使用 SVG 三次贝塞尔曲线（cubic bezier）绘制连续无断点的 2px 连接线：每条连接从父节点右侧中点出发，经平滑曲线过渡到子节点左侧中点；连接线由独立的 `TreeConnectors` 组件通过 `ResizeObserver` 自动测量并实时重绘，折叠/展开与缩放时曲线自动更新，窄屏下间距变量自动收紧。
- 结构灵活性：项目后面既可以直接添加模块，也可以直接添加可执行任务；任务节点还可以再添加一层子任务（更多菜单中的“新建子任务”），子任务本身不能再添加下级；只有叶子任务可以计时、加入今日计划或被拖成子任务。
- 页面背景采用柔和优雅的冷灰、冰蓝与淡紫多层渐变光晕，突出中央任务树的高对比度层次与现代空间感。
- 任务节点采用高对比度半透明 Liquid Glass 材质，具备清晰柔和的边框、背景模糊（`backdrop-filter`）、顶部柔和高光边与立体阴影；所有任务节点严格使用圆角矩形，禁止使用圆形、椭圆、胶囊形或其他几何形状。
- 当任务在今日任务页勾选完成（或达到完成状态）时，即使时间未用完，任务树中对应的任务节点也会实时同步为已完成状态，并在视觉上呈现大号通透的绿色玻璃质感勾选徽标（`✓`）。
- 大纲列表视图同样采用 Liquid Glass 质感（半透明、背景模糊与柔和高光），纵向清晰展示“项目（稳重）→ 模块（轻质）→ 任务（简洁）”层级结构；父任务进入大纲时默认折叠，用户通过节点前的下拉箭头查看或收起子任务，同一父级下的子任务使用一致的缩进、宽度和纵向基线，避免参差错位。
- 点击节点名称或更多菜单中的编辑操作，会打开居中的模态弹窗。新建项目、模块或任务也使用同一弹窗，不再把表单插入到节点下方。
- 面板右上角的“模板库”按钮打开模板管理弹窗；新建项目弹窗顶部提供模板选择行，选中后会预填项目名称与新任务默认值，并预告将要创建的模块与任务。
- 任务列表永远显示全部任务：上级缺失或层级异常的节点会被提升为顶层节点显示，不会因为找不到父级而从页面上消失。
- 全部项目都被“显示已完成项目”开关隐藏时，页面显示“N 个项目已标记完成”的说明和一键显示按钮，而不是一片空白；还有可见项目时在列表上方给出同样的提示。

## API

| 方法 | 地址 | 用途 |
|---|---|---|
| GET | `/api/v1/tasks` | 查询当前用户全部有效任务 |
| POST | `/api/v1/tasks` | 创建任务 |
| GET | `/api/v1/tasks/{task_id}` | 查询单个任务 |
| PATCH | `/api/v1/tasks/{task_id}` | 修改任务、父级、预算或状态；计划用时同步到今天及未来的关联每日任务 |
| DELETE | `/api/v1/tasks/{task_id}` | 软删除任务子树 |
| GET | `/api/v1/project-templates` | 查询当前用户保存的项目模板 |
| POST | `/api/v1/project-templates` | 新建模板（重复的客户端 `id` 视为更新） |
| PATCH | `/api/v1/project-templates/{template_id}` | 修改模板 |
| DELETE | `/api/v1/project-templates/{template_id}` | 软删除模板 |

所有接口都需要：

```text
Authorization: Bearer <access_token>
```

## 预算规则

```text
实际时间 / 预计时间 < 80%      NORMAL
实际时间 / 预计时间 >= 80%     NEAR_LIMIT
实际时间 / 预计时间 >= 100%    EXHAUSTED
实际时间 / 预计时间 >= 150%    SEVERE
```

历史数据中预计时间为 0 时，预算等级仍为 `NOT_SET`；新建可执行任务已在前端强制设置计划用时。
