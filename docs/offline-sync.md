# 离线保存与同步

## IndexedDB 表

| 表 | 内容 |
|---|---|
| `timerStates` | 当前账户的活动计时器（含计划用时 `target_seconds` 与该任务当天已累计的基准 `base_seconds`） |
| `sessionOutbox` | 每个 Session 最新完整快照 |
| `cachedTasks` | 按 `owner_id` 隔离的任务缓存 |
| `cachedDailyPlans` | 按账户和日期隔离的每日计划缓存 |
| `syncOperations` | 任务/计划的有序创建、修改、删除操作 |
| `metadata` | 稳定浏览器 `client_id` |

## 计时同步

每次开始、暂停、恢复或结束时，先持久化本地快照，再尝试上传。相同 Session ID 的旧快照不会覆盖
新状态；完成后的 Session 不可改变时长。

计时器显示的是「`base_seconds` + 本次 Session 时长」：`base_seconds` 是开始这次计时时该任务当天
已累计的秒数，因此结束计时后再次开始会从上次停下的读数继续，而不是从 00:00 重来。它随活动计时状态
一起写入 `timerStates`，页面关闭、崩溃恢复和跨天暂停都会保留。从服务端恢复的活动 Session 没有本地
基准值，今日页读到对应计划项后按「计划项累计时长 − 本次 Session 时长」补上一次。

结束计时上传的快照带 `complete_daily_item=false`：时长照常记录，但任务不会被标记完成，仍可再次开始。
只有“完成任务”按钮和今日任务的勾选框会带 `complete_daily_item=true`。

## 任务与计划同步

1. 离线创建时由浏览器生成 UUID。
2. UI 和缓存立即更新。
3. 操作按严格递增的 `created_at` 进入队列。
4. 联网后按顺序重放，因此项目先于模块、模块先于任务、每日计划先于计划项创建。

任务增删改后的后台刷新按账户做约 0.6 秒防抖合并：连续的添加或编辑只触发一次队列重放与列表
刷新，避免每次操作都产生多轮网络往返和整树重渲染。今日任务新增事项采用本地优先：先写入
`cachedDailyPlans` 与同步队列，再在后台按顺序写入服务端。这样切换回今日任务和添加事项不会被网络往返阻塞；同步状态仍通过页面提示展示。
5. 服务端接受客户端 UUID，并对重复创建返回同一记录。
6. 如果另一设备已经创建同一日期计划，客户端把本地计划 ID 映射到服务端计划 ID，再继续上传计划项。
   计划项创建返回的记录 ID 与请求的本地 ID 不同时（服务端把同一任务的重复条目解析到了已有条目），
   缓存里的本地条目被服务端条目取代，不会留下第二条。
7. 网络错误保留队列；业务冲突保留错误信息，待冲突条件解除后重试。
8. 网络错误的判定范围：请求无响应，或 HTTP 408/425/429/502/503/504。应用层返回的 400/404/409 以及
   500（服务端已处理但拒绝写入，例如数据库层级触发器拦截）按业务冲突隔离计数，不会把整个应用切到
   “离线”状态反复提示；待条件解除（如执行完数据库迁移）后重放成功并清空队列。
   后端把连接池等待超时和断开的连接回成 503（而不是 500），因此数据库繁忙时队列会原样保留并稍后
   重放，不会被误判为“被服务器拒绝”。
9. 任务列表的合并带请求序号：`load` 与 `flush` 可能并发，只有最新一次取回的服务端列表才会替换内存
   列表并清理本地缓存中多余的行。否则一次较早发出、较晚返回的请求会用“还没有这个项目”的旧快照覆盖
   刚刚创建的项目，让它从项目页上消失。仍在同步队列里的本地新建任务永远不会被服务端列表清掉。

项目模板不进入离线队列：模板是蓝图而不是任务数据，直接通过 `/project-templates` 读写。套用模板
创建项目时生成的模块与任务则和手动创建完全一样，逐条进入 `cachedTasks` 与 `syncOperations`。

合并服务端每日计划时，本地缓存里引用同一 `task_id` 的多余条目会被丢弃，其排队中的写入一并撤销：
浏览器的排期导入与服务端的排期补齐各自生成条目 ID，否则同一个任务会在今日任务里长期显示两条。正在
计时的那条条目永远保留，交由服务端在下次 `POST /daily-plans/open` 时按“保留有计时记录的一条”合并。

所有缓存和队列均带 `owner_id`，切换账户不会读取其他账户的离线数据。

Supabase Auth 会话使用独立的浏览器存储键 `dayflow-supabase-auth`，SDK 自动刷新 Access Token；Axios
在内存中缓存未过期的访问令牌，临近过期时重新读取最新会话，并通过 Auth 的令牌刷新与退出事件同步更新
或清空缓存，不把过期令牌复制到业务 IndexedDB。退出登录先通知 Supabase
撤销当前会话，再清理 Pinia 中的账号状态；业务离线数据仍按 `profile.id` 隔离。

任务、每日计划、计时快照和同步队列在写入 IndexedDB 前统一转换为可序列化的普通对象，避免 Vue
响应式代理或代理数组触发 `DataCloneError`。浏览器存储异常不会直接把英文技术信息显示给用户，而是
通过统一错误翻译层显示中文操作建议。
