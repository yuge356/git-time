# 模块 3：学习计时器与 Session

## 本模块范围

- 开始学习
- 暂停计时
- 恢复计时
- 结束计时（保留已计时时长，任务保持可继续）
- 直接标记任务完成
- Session 独立存储
- 同一账户仅允许一个运行中或暂停中的 Session
- 实际学习时长按 Session 汇总
- 父任务实际时长包含全部子任务
- Dexie 保存本地活动计时状态
- 断网时保存最新 Session 快照并在联网后重试
- 页面刷新、浏览器后台和设备休眠后的准确计时
- 关闭网页时自动暂停计时；跨越本地午夜时在 00:00 自动暂停，避免同一段计时跨入新的每日计划
- 计时达到任务的计划用时时，每个 Session 只显示一次站内提醒，并在用户授权后同步发送浏览器系统通知
- 达到计划用时不会自动结束或暂停，实际计时继续累计，由用户手动暂停或结束
- **结束计时与完成任务是两件事**：专注计时卡片提供“结束计时”和“完成任务”两个按钮，今日任务列表里的
  “结束”按钮同样只结束计时。结束计时会保留本次记录的时长并把条目留在未完成状态，任务提前结束、计划
  用时还有剩余时，可以随时再次开始
- **再次开始从上次停下的时间点继续计时**：计时器显示的是该任务当天累计的时长（上次停止时的读数 + 本次
  Session），不会从 00:00 重新数。上次的读数保存在本地计时状态里（`base_seconds`），从服务端恢复的
  计时会在今日页读到计划项后补上这个基准值
- **任务可以直接标记为已完成**：今日任务的勾选框在计时进行中同样可用，勾选会先结束当前计时再完成任务，
  因此已计时的秒数一定被记录下来。统计时间一律以在本软件中计时的 Session 为准，直接标记完成不会补记
  任何未计时的时长
- 专注计时卡片、今日任务列表和全局计时条读取同一个计时值（`timer.totalSeconds`），三处显示必然一致；
  服务端在计时过程中刷新数据时也不会把正在进行的这段时长重复计入“已投入”
- 活动计时对应的项目任务修改计划用时后，计时目标立即切换为新值，已累计的实际时长保持不变
- 今日任务列表底部和进度色块使用纯色透明层，不再显示紫色渐变背景
- 今日页面右侧的任务列表卡片高度固定在空状态时的尺寸：添加任务不会把卡片拉长，任务超出容量后列表内部出现垂直滚动条（约 250px 高的列表区域，与空状态占位等高，可视区可同时展示约两个半任务卡片），用户在列表内滑动查看全部任务；列表与“添加今日任务”之间的留白保持紧凑（约 10px 间距），把纵向空间留给任务内容；卡片的宽度也保持不变，“添加今日任务”展开的表单始终收在卡片宽度以内（长任务名的下拉框自动收缩，放不下时换行），不会把卡片或整页撑宽
- 今日页面专注计时和任务列表下方是计划进度表，用来查看项目的时间跨度，**不承担编辑与创建**（排期在任务编辑弹窗的“安排时间”里调整）：
  - 时间轴支持天 / 周 / 月三档切换且选择保存在本地，表头双层刻度并保持固定；今天用紫色竖线与“今日”标签标记，天视图下周末列使用浅色底纹
  - **默认折叠**，每个项目一行，显示该项目全部任务合并后的时间跨度、平均进度与累计时长；标签列同时给出日期区间，长条滚出视野时也能读到
  - 展开后按模块分行（直接挂在项目下的任务归入“项目直属任务”），模块线上的每个方块是一项任务；同一模块内时间重叠的任务自动排到不同泳道，行高随泳道数增长，互不遮挡
  - 任务的方块覆盖“计划窗口 ∪ 实际记录”的完整跨度，填充比例表示完成进度；只有当计划窗口和实际记录确实不一致时，才额外叠加一个虚线框做对比
  - 悬浮项目条或任务方块显示详情浮层；点击任务方块跳转到项目页，自动展开所属项目并定位到该任务
  - 支持按住拖拽平移与横向滚动，手机端自动切换为卡片视图
- 今日专注分布柱状图按小时统计：仅展示用户选定的单独一天，不会生成多天的柱子；X 轴为一天各时刻（24 根圆角加宽柱体），Y 轴为对应小时的学习时长，Session 归属到计时开始的小时；鼠标悬浮柱形弹窗显示该时刻与该小时累计学习时长，正在计时的时长实时计入当前小时柱体；卡片右上角提供日期切换控件（前一天/后一天按钮 + 日期选择器，未来日期不可选），可回看历史某一天的柱状图；查看历史日期时标题与汇总文案随之切换，且不叠加实时计时

- 今日页面首次加载时，月历趋势、单日专注分布与计划进度表通过 `GET /analytics/today-overview`
  一次取回。此前三个独立请求会同时占满后端很小的数据库连接池，超出的请求超时后页面就会在空白
  图表上显示“服务器处理请求时出错”的红色提示。切换月份或回看历史某天时仍走各自的单独接口。
- 今日页各个面板独立加载：任务、每日计划与图表任一失败都不会清空其余面板，错误只显示在对应位置。
- 打开某一天只发一个 `POST /daily-plans/open` 请求（取得或创建计划、按排期补齐、读取打卡），
  此前是三到四个串行请求；任务列表与当日计划都先用 IndexedDB 缓存立即渲染，再后台替换为服务端数据。
- 计时进行中的时长会实时汇总到项目页对应任务、模块与项目的进度条与已用时间上。
- 安排在今天的项目任务会自动出现在今日任务里：截止日期为今天、重复规则命中今天，或今天落在任务的
  计划窗口（安排开始～安排结束）内。批量导入时只触发一次同步请求，不再为每个任务各发一次。
- **一项任务在一天里只会出现一条**。浏览器导入新排期的任务和服务端 `open` 的排期补齐会同时发生，两边
  各自生成条目 id，此前会让在项目里排期的任务在今日任务出现两次。现在四道防线共同保证唯一性：前端
  导入有并发锁并跳过当天已有的任务；服务端 `POST /daily-plans/{id}/items` 对同一任务返回已有条目；
  合并服务端计划时丢弃本地重复条目并撤销它排队中的写入；`open` 会合并历史遗留的重复条目（保留有计时
  记录或已完成的那条）。正在计时的那条永远不会被丢弃。

本模块没有提前实现每日计划、打卡、统计图表或伙伴功能。

## 可靠计时方式

前端不依赖每秒加一作为真实数据，而是保存：

- `started_at`
- `duration_seconds`
- `last_resumed_at`
- `client_updated_at`

运行中的显示时间为：

```text
duration_seconds + 当前时间 - last_resumed_at
```

因此浏览器进入后台或设备休眠后，恢复页面仍能计算正确时长。

关闭或刷新网页时，页面生命周期处理器会先写入同步的本地暂停标记，并通过保活请求尝试写入服务端；下次打开时即使上次请求未完成，也会先恢复该暂停快照。计时器的全局时钟会检测本地日期变化，运行中的计时会按新一天的 `00:00` 作为暂停边界；切换站内页面不会触发暂停。

## 离线同步

Dexie 数据库包含：

```text
timerStates
sessionOutbox
metadata
```

每次开始、暂停、恢复或结束时：

1. 先把完整 Session 快照写入 IndexedDB。
2. 在线时立即调用后端同步。
3. 断网时保留同一 Session 的最新快照。
4. 网络恢复后按 `client_updated_at` 顺序提交。
5. 后端忽略旧快照，避免重复累计。

暂停、恢复和结束的**按钮忙碌窗口只覆盖本地快照写入**（约几十毫秒）：远程同步在后台进行，
失败时快照留在 outbox 由离线同步重放，因此操作后 UI 立即回到可交互状态，用户可以马上添加
下一个任务。唯一例外是退出登录前的最后一次暂停会等待同步完成，确保服务器已持有最终快照。

刷新网页后计时显示的恢复同样优先走本地：活动快照在 IndexedDB 中时立即恢复显示，outbox 重放与
历史列表拉取在后台进行；本地无快照（如更换设备或清理存储）时只等待一次 `GET /sessions/active`
即恢复显示，待重放队列非空时先重放再恢复，避免恢复出过期状态。

本地数据按账户 ID 隔离，切换账号不会读取其他账号的活动计时状态。

## Session API

| 方法 | 地址 | 用途 |
|---|---|---|
| GET | `/api/v1/sessions` | 查询最近 Session |
| GET | `/api/v1/sessions/active` | 查询活动 Session |
| PUT | `/api/v1/sessions/{session_id}` | 幂等创建或更新完整快照 |

`PUT` 使用客户端生成的 UUID。相同状态可以安全重试，服务端通过
`client_updated_at` 忽略过期快照。

## Session 状态

```text
RUNNING   正在计时
PAUSED    已暂停，可以恢复或结束
COMPLETED 已结束，不允许再修改时长
```

## 任务预算汇总

- 子任务的 Session 计入子任务直接时长。
- 父任务总时长包含自身直接时长和所有后代任务时长。
- 活动 Session 会包含当前尚未落库的运行区间。
- 任务预算提醒继续使用 80%、100%、150% 阈值。

## 计划进度表

今日页面专注计时和任务列表下方（月度计时日历与专注分布之上）展示计划进度表，用来**查看项目的时间跨度**——它是只读视图，创建与排期都在别处完成：

- 数据来自 `GET /api/v1/analytics/today-overview` 中的 `task_daily`，按资料时区把每个 Session 的有效时长归属到计时开始当天，与 `daily_trend` 的归属规则一致；前端固定取最近 366 天。
- 顶部统计栏展示总学习时长、活跃任务数、完成率（已完成任务占图表内全部任务的比例）与连续学习天数（按全部学习日期的并集，从今天或昨天向前连续计数）。
- 时间轴支持天 / 周 / 月三档切换，选择保存在浏览器本地（`dayflow:today-gantt-scale`）；表头为双层刻度（上层年月、下层日期 / 周起点 / 月份），名称列与日期表头在滚动时保持固定。今天使用紫色竖线加“今日”标签标记；天视图下周末列使用浅色底纹，月份边界线略深、其余网格线保持极淡。打开图表或切换尺度时自动滚动到今天附近，可按住鼠标拖拽平移。
- **默认折叠**：每个项目一行，条形覆盖该项目全部任务合并后的时间跨度，填充比例是各任务进度的平均值；名称列同时显示日期区间与累计时长，长条滚出视野时也能读到。标题栏提供“全部展开 / 全部折叠”。
- **展开后按模块分行**：直接挂在项目下的任务归入“项目直属任务”。模块线上的每个方块是一项任务；同一模块内时间重叠的任务自动分配到不同泳道，行高随泳道数增长，任务之间互不遮挡。
- 任务方块覆盖“计划窗口 ∪ 实际学习记录”的完整跨度，内部填充表示完成进度；只有当计划窗口与实际记录确实不同时，才在方块后叠加一个虚线框做对比，避免画出一条描着方块轮廓的虚线。
- 悬浮或键盘聚焦项目条 / 任务方块时弹窗展示名称、所属项目与模块、状态、开始与结束日期、累计学习时长、持续 / 活跃天数与进度。**点击任务方块跳转到项目页**（`/tasks?task=<id>`）：目标项目自动展开、任务详情弹窗打开并滚动定位到该节点。
- 图表包含有正时长学习记录的任务（含已删除任务，按删除前标题显示并归入“未关联项目”分组）以及已设置安排时间但还没有学习记录的任务；临时事项（无关联任务的 Session）不计入。
- 桌面与平板显示完整时间轴（窄容器自动压缩日期列宽与名称列宽度）；手机端（视口 ≤ 639px）自动切换为按项目分组的卡片视图。
- 整个组件不再提供拖拽排期：任务的安排起止日期在项目页任务编辑弹窗的“安排时间”分区里设置，图表只负责呈现。
